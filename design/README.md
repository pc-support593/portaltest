# Handoff: 株式会社吉村一建設 社内ポータル

## Overview

社内ポータルサイト一式のデザイン。3画面構成。

1. **社内ポータル トップ** — お知らせ、クイックリンク、今日の予定、全社スケジュール、タスク・承認待ち
2. **会議室予約** — 展示場(拠点)別・会議室別の月間カレンダー、予約の作成/変更/取消、CSV出力
3. **管理画面** — お知らせ / 全社スケジュール / クイックリンクの CRUD

Microsoft 365(Exchange / Entra ID)連携を前提とした設計。予定・会議室・予約は Microsoft Graph API 経由で取得・作成する想定。

## About the Design Files

`prototypes/` に入っている HTML は **デザインリファレンス** です。見た目と挙動を示すプロトタイプであり、本番コードとしてそのまま使うものではありません。

実装タスクは、これらの HTML デザインを **対象コードベースの既存環境(React / Next.js など)で再現すること** です。環境がまだ無い場合は、プロジェクトに適したフレームワークを選定した上で実装してください。

各 HTML は単体で開けます。相互リンクがあるため、3ファイルは同じフォルダに置いてください。

- `prototypes/portal_v2.html` — 社内ポータル トップ
- `prototypes/rooms_v2.html` — 会議室予約
- `prototypes/admin_v2.html` — 管理画面

プロトタイプ内のデータはすべてダミーです。予約データは `localStorage`(キー: `yoshimura-room-bookings`)、管理画面のデータは `yoshimura-portal-admin-v2` に保存しています。本番では Graph API / データストアに置き換えてください。

## Fidelity

**High-fidelity (hifi)**。色・タイポグラフィ・余白・インタラクションは確定値です。既存コードベースのコンポーネントライブラリを使いつつ、見た目はこのまま再現してください。

## Screens / Views

### 1. 社内ポータル トップ (`portal_v2.html`)

**Purpose** — 社員が朝一番に開くホーム。お知らせ確認、各システムへの導線、当日の予定とタスク把握。

**Layout**

- ヘッダー(高さ 54px、`#1e3a5f`): ロゴ+社名 / ナビ(ホーム・社内規程・組織図・会議室予約・管理) / 右に検索インプット(幅 250px、半透明白 12%)、通知ベル(赤ドット付き)、ユーザーアバター+氏名+部署
  - レスポンシブ: `max-width:1100px` で検索を非表示、`max-width:760px` でナビを非表示
- 挨拶行: `{時間帯に応じた挨拶}、佐藤さん` + 当日日付
- メイン: `grid-template-columns: repeat(auto-fit, minmax(460px, 1fr))`、gap 18px、`align-items:start`
  - 左列: お知らせ / クイックリンク
  - 右列: 今日の予定 / 全社スケジュール / タスク・承認待ち
- フッター: 中央寄せ 12px `#8a99a8`

**Components**

- **お知らせ** — 各行はボタン。`[カテゴリバッジ] [タイトル] …… [日付]`。行クリックで詳細モーダル。
- **詳細モーダル** — カテゴリバッジ+掲載日、タイトル 19px/700、本文(`white-space:pre-wrap`、line-height 1.9)、フッターに発信部署と閉じるボタン。最大幅 640px、`max-height:80vh`。
- **クイックリンク** — 4列グリッド、各タイルは 38px 角丸アイコン(1文字)+ラベル。枠 `#e4eaf1`、hover で `#f5f8fb` + 枠 `#c8dcf0`。8項目(勤怠管理/経費精算/各種申請/会議室予約/工事台帳/図面管理/社員名簿/ITサポート)。「会議室予約」は `rooms_v2.html` へ遷移。
- **今日の予定** — 「Outlook 連携」バッジ付き。各予定は左ボーダー 4px の色分けカード(青 `#2e6fc0` / 緑 `#2e7d52` / 橙 `#d97b3f`)。時刻 13px/700 + 件名 14px/700 + 場所 12px。
- **全社スケジュール** — 左に日付チップ(月/日、`#eef3f9`)、中央に行事名+補足、右に `›`。クリックで詳細モーダル(お知らせと共通)。
- **タスク・承認待ち** — 見出し右に件数ピル。各行に種別バッジ(承認/提出/回答)+件名+システム名・期限+「確認」ボタン。

### 2. 会議室予約 (`rooms_v2.html`)

**Purpose** — 展示場・会議室単位の空き状況確認と予約。

**Layout(上から)**

1. ヘッダー(トップと同じ意匠、右に「Exchange 連携」バッジ + ポータルへ戻る)
2. **拠点タブ行** — ラベル「拠点」+ 4つのボタン(平野展示場 / 花博展示場 / 中百舌鳥展示場 / 福田展示場)。各ボタンに室数。選択中は `#1e5fa8` 塗り+白文字。
3. **会議室タブ行** — ラベル「会議室」+「全ての会議室」+ 拠点内の各室。各ボタンは色ドット+室名+定員などのメタ。選択中は背景 `#eef4fb`、枠 `#2e6fc0`。右端に凡例(主催/参加)と **「＋ 新規予約」ボタン**(`#1e5fa8` 塗り)。
4. **カレンダーカード**(全幅)

**カレンダー**

- ヘッダー: 会議室色ドット + `{拠点名} {会議室名}` + メタ / 右に `‹` `{YYYY年 M月}` `›` `今月` `CSV出力`
- 週の起点は **月曜**。曜日ヘッダーは 月火水木金土日。土 `#2f6f8f`、日 `#c05a5a`。
- グリッド: `grid-template-columns: 46px repeat(7, 1fr)`。左端 46px 列は **週選択ボタン**(縦書き「第N週」)。押すとその週のみ表示に切り替わり、上部に青帯「◯日〜◯日の週を表示中」+「月間表示に戻る」が出る。再クリックで月間に戻る。
- 日セル: `min-height:118px`。日付は 22px 円(当日は `#1e5fa8` 塗り+白文字)。右上に件数。土日・当月外は背景を変える(当月外 `#fbfcfd` / 日 `#fdf7f7` / 土 `#f7fafd`)。
- **予約枠(2行構成)** — 背景は会議室色のベタ塗り、文字は白抜き。左ボーダー 4px は関与ステータス色。
  - 1行目: `10:00–11:00` / `/ 会議室A` / `[主催|参加]` / `佐藤`(**名字のみ**)
  - 2行目: 件名
  - 件数が多い日はセルが縦に伸びる(省略しない)

**日別ポップアップ**(日セルをクリック)

- 単室選択時: 8:00〜18:00 の1時間刻み。予約がある時間は会議室色ベタ塗り+白抜き、空き時間は淡色 + 「予約する」ボタン。
- 「全ての会議室」選択時: その日の全室の予約を時刻順に列挙(空きスロットは出さない)。
- 予約行は2行: 1行目 `時刻 / 会議室名 / [主催|参加]`、2行目 `件名 + 主催者フルネーム`。
- 自分が主催の予約には「変更」「取消」ボタン。参加のみの予約には出さない。
- フッター: 「予約は Outlook の予定表に反映されます」+「＋ 時間を指定して予約」(単室時のみ)+ 閉じる。

**予約フォーム(モーダル、最大幅 520px、`max-height:88vh`、本文のみスクロール)**

- 見出しは新規なら「会議室を予約」、変更なら「予約を変更」
- 新規予約(トップの「＋ 新規予約」)からは **展示場 / 会議室 / 日付** のセレクトを表示。時間帯クリックからの起動時は対象が確定しているため、代わりに `{拠点} {会議室}` と日付のサマリー行を表示。
- 共通項目: 件名(必須) / 開始・終了(8:00〜20:30 の30分刻みセレクト) / **社内メンバー** / **外部参加者**
- **社内メンバー** — 「Microsoft 365」バッジ付き。名前・部署・メールでインクリメンタルサーチ(最大5件表示)。候補クリックで追加、選択済みはアバター付きチップ(`#e9f1fa` / 枠 `#c8dcf0`)で表示し ✕ で個別削除。→ 実装では Graph `/users` に置換。
- **外部参加者** — 自由入力(例: ○○商事 山田様 2名)
- バリデーション: 終了 ≤ 開始 → 「終了時刻は開始時刻より後にしてください」、会議室未選択 → 「会議室を選択してください」。件名空欄は送信不可。
- フッター: 変更時のみ左に「この予約を取消」、右に キャンセル / `予約する`|`変更を保存`
- 保存後は該当の拠点・会議室・月へ自動で切り替えて結果を表示。

**CSV出力**

- 表示中の拠点・会議室(「全ての会議室」時は全室)の**当月分**を出力
- 列: 拠点 / 会議室 / 日付 / 曜日 / 開始 / 終了 / 件名 / 予約者
- ファイル名 `会議室予約_{拠点名}_{YYYYMM}.csv`、BOM 付き UTF-8(Excel対応)、全セルダブルクォート囲み

**拠点・会議室マスタ(プロトタイプの値。本番は Graph `/places` から取得)**

| 拠点 | 会議室 |
|---|---|
| 平野展示場 | 会議室A(3F・12名・TV会議) / 会議室B(3F・6名・モニタ) / 大会議室(1F・40名・配信設備) / 応接室(2F・4名) |
| 花博展示場 | 会議室1(5F・10名・TV会議) / 会議室2(5F・6名) / 応接室(5F・4名) |
| 中百舌鳥展示場 | 打合せ室(2F・8名・モニタ) / 小会議室(2F・4名) |
| 福田展示場 | 商談室(1F・8名) / セミナールーム(2F・20名) |

## Interactions & Behavior

- **ナビゲーション** — ポータル ⇄ 会議室予約 ⇄ 管理画面 は通常のページ遷移。
- **モーダル** — 背面オーバーレイのクリックで閉じる(内側は `stopPropagation`)。✕ ボタンとフッターの閉じるボタンでも閉じる。
- **hover** — ボタンは背景/枠色の変化のみ。トランジションは付けていない(必要なら 120ms ease で統一)。
- **週表示** — 月移動・「今月」・拠点/会議室の切替時は週選択を解除して月間表示に戻す。
- **予約の権限** — 変更・取消は主催者のみ。参加者には操作ボタンを出さない。Exchange 側でも主催者以外の削除は 403 で弾かれる。
- **レスポンシブ** — PC 中心。`max-width:900px` で会議室予約のレイアウトを1列化。ポータルのメイングリッドは `auto-fit` で自動的に1列になる。

## Microsoft 365 連携(実装方針)

| 機能 | エンドポイント |
|---|---|
| 会議室一覧 | `GET /places/microsoft.graph.room`(または Room List) |
| 空き状況 | `POST /me/calendar/getSchedule`(会議室のメールアドレスを指定) |
| 予定取得 | `GET /me/calendarView?startDateTime=&endDateTime=` |
| 予約作成 | `POST /me/events`(会議室を `attendees` の `type: "resource"` で指定) |
| 予約変更 / 削除 | `PATCH` / `DELETE /me/events/{id}` |
| 社内メンバー検索 | `GET /users?$search="displayName:{q}"` |

- 認証: MSAL.js による Entra ID SSO(委任権限)
- 必要権限: `Place.Read.All`, `Calendars.ReadWrite`, `User.Read.All`(管理者同意が必要)
- 同期方式: **リアルタイム取得**(表示中の月・会議室のみ都度取得)を推奨。定期バッチ同期は同期の谷間で二重予約が起きるため会議室予約には不向き。
- 主催者判定: `organizer` と `attendees` を照合して「主催 / 参加 / 無関係」を決定する。
- 管理者による代理削除が必要な場合は、Room mailbox へのフルアクセス権限付与、または `Portal.Admin` ロール + アプリケーション権限で実装。削除ログと主催者への通知をセットで用意することを推奨。
